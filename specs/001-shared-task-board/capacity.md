# Local capacity sample

Run `pnpm exec tsx scripts/measure-capacity.ts` to execute the sample against isolated test D1. It inserts 1,000 synthetic tasks and reads no real board data.

On 2026-11-03, local Miniflare reported two rows read for partner authorization, one row read for the unchanged revision lookup, 1,000 rows read for a full changed-board query, one row read and one row written for a non-indexed title update, and one row read and two rows written when updating indexed creation time. Serializing the sampled 1,000 rows produced 179,891 bytes; the local timer reported 1 ms elapsed. A loop of 100 cached-key signed-token verifications reported 5 ms elapsed in the same local Worker test runtime. Separately, Node process CPU measurements for 100 iterations recorded 20,089 microseconds for token verification and 14,876 microseconds for serializing a 1,000-task board. These local measurements are not production Worker CPU billing. D1 reported a database size of 204,800 bytes for this synthetic sample.

For two visible clients, 15-second polling produces 11,520 scheduled requests/day before immediate or extra-tab refreshes. The revision and authorized-partner lookups account for approximately 34,560 row reads/day when unchanged in this local sample, compared with the original 23,040-row estimate. At 100 saves/day and 1,000 tasks, two full refreshes per save add roughly 200,000 task rows/day. These are estimates, not quotas or limits on task count.

The indexed-field comparison includes the index maintenance in D1’s total rows-written metadata; it does not separately expose bytes or all index effects. The available local timing did not measure production CPU usage. Measure Worker token verification and serialization CPU, actual D1 `rows_read`/`rows_written`, indexes and shared-account usage in the production environment before release; compare with the current service quotas. Data growth, request bursts and quota failures remain operational constraints.
