# Implementation validation

This evidence records local checks; it does not claim final acceptance or a production release.

- **Local setup:** Node 24 and pnpm 12.16.1; local D1 migrations and demo Auth fixtures succeeded. Reseeding preserved the existing revision and restored the same partner UIDs after an emulator restart. No production credentials, real accounts or deployment were used.
- **Typecheck and unit:** TypeScript checks and 51 unit tests passed before the final browser run. Tests cover validation, signed-token verification, transport timeouts and ETags, refresh ordering, deadline conversion, complete snapshot validation and storage/cleanup failures.
- **D1 integration:** the most recent run passed 17 tests, including access checks, routing, concurrent replacements, no-op saves, revision overflow, transaction rollback and a save racing a board read. The capacity sample uses a separate isolated 1,000-task test database.
- **Browser:** the latest complete built-Worker matrix passed 112 tests across Chromium, Firefox, WebKit and mobile Chromium/Safari profiles, with three intentional skips of the Chromium-only live time-zone override. The account-switch and 401/403 cleanup tests were then rerun with the actual mobile viewport/touch profiles: six passed. A previous parallel run had two WebKit context-teardown timeouts after assertions passed; the full serial rerun passed.
- **Deadline evidence:** Guatemala 2026-11-02 09:00 was displayed in Madrid at 16:00 UTC+01:00. New York's 2027 spring gap was rejected and autumn fold chose UTC−04:00; removal and device-zone review passed. An interactive Chromium keyboard review entered a date and time, selected an assignee using native type-ahead, saved the task and returned focus to the create button. Keyboard focus, Escape and focus return, a 320px layout and a 200% zoom primary flow also passed automated Chromium and Firefox checks; broader browser evidence is in `accessibility.md`.
- **Privacy decision:** failed cleanup blocks restoration through IndexedDB, localStorage and a fallback cookie marker. If all three mechanisms fail to persist during cleanup and every tab closes, that pending state cannot be recorded. The user chose to preserve offline reopening and accept the exceptional possibility of restoring an old same-UID snapshot before fresh authorization.
- **Still outstanding:** each actual partner must independently time the create/assign/complete flow; manual screen-reader and keyboard/date-entry review remains to be performed. No physical Android Chrome or iPhone Safari/Home Screen device was available in this environment. Production signed-token smoke tests and real quota/CPU measurements remain release checks. Do not treat automated emulation as physical-device acceptance.
